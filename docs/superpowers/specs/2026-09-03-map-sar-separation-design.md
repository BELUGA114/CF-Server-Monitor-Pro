# 地图区域分离：大陆（含海南）/ 香港 / 澳门 · 设计

日期：2026-09-03

## 背景

首页地图（Leaflet，`src/index.js:2489-2531`）把节点按国家代码聚合后做两件事：

1. 用 `iso2To3` 把代码映射成 ISO3，在世界边界图层上给对应国家填绿（`#10b981`）。
2. 用 `countryCoords` 里的硬编码质心放一个数字徽章。

数据层其实已经分开了：`/update` 存的 `country` 取自 `request.cf.country`（`src/index.js:1582`），CF 对港澳返回独立代码 `HK` / `MO`，所以 `countryStats`（`src/index.js:1801-1803`）里本来就是三个 key。问题全在渲染层。

已核实的三个事实（对 `cdn.jsdelivr.net/gh/johan/world.geo.json@master/countries.geo.json` 做要素统计与点在多边形内测试）：

- 该数据集共 178 个要素，有 `CHN` 和 `TWN`，**没有 `HKG`，也没有 `MAC`**。
- 香港中环 `[114.155, 22.282]` 落在 `CHN` 多边形内 —— 香港的地块被中国的色块吞掉，`iso2To3` 里的 `HK -> HKG` 永远匹配不到要素。
- 澳门 `[113.55, 22.20]` 落在**所有**要素之外（该数据集在珠江口的岸线很粗，珠海也在外面）。加上 `countryCoords` 和 `iso2To3` 都没有 `MO`，澳门机器在地图上既没有色块也没有徽章 —— 完全不可见。

海南方向已确认无需处理：海口 `[110.20, 20.04]` 与岛中部 `[109.75, 19.20]` 都落在 `CHN` 内，本来就跟大陆一起亮。

## 目标

地图上把 **大陆（含海南）/ 香港 / 澳门** 三者的色块与数字徽章分别呈现，按机器上报时 CF 判定的位置归类。

## 非目标

- 不把海南从大陆里拆出来（用户明确：海南算中国）
- 不动 `TW -> CN` 的归一化（`src/index.js:1583`、`src/index.js:1802`）
- 不动筛选标签与卡片国旗（`MO` 在 flagcdn 上有旗，现有循环已能正常渲染）
- 不换世界边界数据集（换 50m/10m 会把 250KB 抬到几 MB，且要重新核对 feature id 与台湾要素）
- 不改根目录 `workers.js`（历史副本）
- 不增加运行时外部依赖

## 选定方案

在现有世界图层之上再叠一个只含香港、澳门的图层，用**完全相同的 style 函数**；港澳边界离线抽稀后内嵌进 `src/index.js`。

配色语义不变：绿 `#10b981` = 该区域有机器，灰 = 没有；分界靠描边（浅色主题 `#ffffff`、深色主题 `#1a202c`，`weight: 1`）。因此只有大陆有机器时，香港是中国绿块里的一个灰点；只有港澳有机器时，反过来。

## 改动点（全部在 `src/index.js` 首页地图那段浏览器 JS）

### 1. 内嵌港澳边界常量

新增常量 `SAR_GEOJSON`，内容是 `FeatureCollection`，两个要素 id 为 `HKG` / `MAC`，与 `iso2To3` 的取值对齐。

- 来源：阿里 DataV 省级边界 `areas_v3/bound/810000.json`（香港，原始 89KB）与 `820000.json`（澳门，原始 2.2KB）。
- 离线处理：只保留外环，按面积阈值丢掉细碎岛礁，Douglas-Peucker 抽稀（闭合环先在最远点处断成两段开放折线再抽稀，避免首尾同点导致算法退化），坐标保留 3 位小数（约 110m）。
- 抽稀参数：香港容差 0.006°（约 600m）、面积阈值 1e-4 deg²；澳门容差 0.003°、面积阈值 1e-5 deg²（澳门总面积仅约 0.003 deg²，套同一组阈值会丢掉半岛）。
- 产物规模：香港 18 块 / 234 点，澳门 2 块 / 16 点，`JSON.stringify` 后 4529 字节。

### 2. 叠加图层

先把现有 `L.geoJSON(worldGeoJson, { style: function(feature) {...} })` 里的匿名 style 回调提取成一个具名函数（`regionStyle`），两个图层共用同一份配色与描边规则，避免日后改一处漏一处。

然后在 `geoJsonLayer` 之后创建 `sarLayer = L.geoJSON(SAR_GEOJSON, { style: regionStyle }).addTo(window.myMap)`。因为后加所以在上层，港澳的填色状态与大陆互不影响。

`iso2To3` 补 `'MO': 'MAC'`（`'HK': 'HKG'` 已有），这样 `activeIso3` 能同时点亮两个新要素。

`drawMarkers()` 开头移除旧图层的分支要一并移除 `sarLayer`，否则每 4 秒的轮询刷新都会多叠一层。

### 3. 澳门徽章坐标

`countryCoords` 补 `'MO': [22.20, 113.55]`（已验证该点落在抽稀后的 `MAC` 要素内）。

### 4. 港澳徽章像素错位

香港与澳门相距约 60 公里，默认视图 zoom 2 下不到 2 像素，两个 22px 徽章会完全重叠。做法是给这两个徽章设固定 `iconAnchor` 偏移：

- 香港 `iconAnchor: [-1, 19]` → 徽章中心相对真实坐标右移 12px、上移 8px
- 澳门 `iconAnchor: [23, 3]` → 左移 12px、下移 8px

两者中心恒定错开约 29px（大于 22px 徽章尺寸），任何缩放级别都不叠。其余国家继续用默认居中锚点。

代价：高倍缩放下港澳徽章偏离真实坐标十几像素（zoom 10 约 2 公里），可接受。

## 已知取舍

默认世界级视图（`setView([30, 10], 2)`）下香港约 1-2 像素、澳门更小，色块层面的分离要放大到 zoom 6 以上才看得清；默认视图靠三个错开的徽章体现分离。这是「同一绿色 + 描边分隔」这一配色选择的必然结果，不是实现缺陷。

## 验证

已执行：

- `node --check src/index.js` 通过。
- 把模板字符串里浏览器端的 `initMap` / `drawMarkers` 区段还原转义后单独 `node --check`，通过。（`node --check src/index.js` 只校验 Worker 外层，模板字符串内部的浏览器代码对它只是字符串。）
- 用桩替换 Leaflet 与 DOM，直接驱动源码里那段真实代码跑了 18 项断言：港澳图层要素恰为 `HKG` / `MAC`；三区域都有机器时各自填绿；只有大陆时港澳保持灰、只有港澳时大陆保持灰；轮询重绘时两个图层都被移除且不叠加；数据未变时不重建；深色主题下两个图层描边一致。
- 点在多边形内测试：香港徽章坐标、香港中环、澳门徽章坐标、澳门氹仔四点分别落在对应要素内。

## 遗留观察（本次未改）

`drawMarkers()` 开头的 `if(!window.myMap || !worldGeoJson) return;` 意味着上游 CDN 拉不到世界边界时，整张图连徽章都不画。港澳边界现在是内嵌的、不依赖网络，理论上可以在世界图层缺失时仍画出来，但那样只会得到蓝底上两个绿点，不见得更好。此处保持原有行为。
